# 自动化 / 编程游戏 UI/UX 调研与改版判断

调研日期：2026-10-02。目标玩家：高中数学基础、没有深度学习经验。目标产品：PC / Unity / Steam，鼠标键盘优先。

这次改版的问题不是缺少一张漂亮背景，而是任务、零件、线路、教学、调试和训练没有形成清楚的操作层次。应先重组玩家的工作流程，再定义视觉语言。

## 调研方法与证据边界

资料包括开发者官网、官方手册、开发日志，以及开发者发布在 Steam 的实机截图。区分三类内容：**来源明确的产品功能**、**从截图观察到的布局**、**针对本游戏提出的设计推论**。没有声称完成这些游戏的全流程体验或用户访谈；商店截图可能不是最新运行版本。Factorio #212 中的界面明确是开发过程中的草图，不把它作为成品截图。

商业游戏的截图只作为查看和分析的参考，不下载进项目、不作为我们的游戏素材。字体从官方开源仓库取得，许可随文件保存。

## 现有 Unity 界面的具体问题

检查对象：`FoundryGame.cs` 的 Menu / Map / BuildWorkshop / Instruments / Select，以及 `WorkshopUI.cs` 的基础组件、模块和绘图。

| 现象 | 玩家受到的影响 | 改法 |
| --- | --- | --- |
| 每个页面都铺满同一张工坊插画 | 线路编辑时仍有复杂背景，与读数竞争 | 实际操作区使用平整工程板；叙事插画只用于少量非操作场景 |
| 青绿色发光、圆角、铆钉被用于几乎所有容器 | 教学页、工具栏、模块、仪表看起来属于同一层级 | 按物体角色区分：纸页、面板、部件、仪器；明确哪些地方需要边框 |
| 左侧长期放六段教学，零件却在画布下方 | 找工具和读课文的视线持续往返 | 左侧只放当前可用零件；任务在上方；详细教学放手册 |
| 选中模块时重建整块仪表，训练控件消失 | 玩家需要“返回仪表”才能继续实验 | 属性在右，读数在底部；两种信息有独立生命周期 |
| 一次测量、训练、验收、撤销、重置权重接近 | 不知道当前最应做的动作 | 测量是即时操作；训练是一种运行状态；验收是独立规格检查；撤销是弱工具 |
| 验收失败立刻弹阻断窗口 | 每次试错都打断装配 | 在读数区显示错误，定位对象；仅重置等确认操作用模态窗口 |
| 整棵 55 节点树一次纵向堆出大量未来内容 | 当前目标被计划内容淹没 | 先显示当前章节及边界依赖，整树作为总览 |
| 模块端口叫“输入 1 / 2” | 隐藏了封装时建立的接口契约 | 显示真实接口名 x / z，后期加形状、类型和语义 |
| 字体依赖玩家系统 | 商用发行时字形与排版不稳定 | 包含可分发字体；中文说明与数字仪表使用不同字体职责 |

## 五条设计判断

1. **空间稳定**：从装配切到调试、训练，线路的位置不跳动。开合底部读数区，不重新生成整台设备。
2. **解释紧贴结果**：错误定位到端口；梯度贡献指向路径；张量形状指向接口。避免只有顶部泛泛的失败文案。
3. **语义比装饰先行**：橙色用于选择与主操作，蓝色用于前向信号，紫色用于梯度，绿色用于通过。材质不能替代状态标识。
4. **教学只多走一步**：当前任务给一个概念、一项动作、一个观察点；更多推导放手册。每个首次出现的模块仍必须有专门关或首次介绍。
5. **成果属于玩家**：装置命名、封装盒、训练快照、修复记录应围绕玩家造出的东西组织，首页不是指标看板。

## 素材结论

不使用一整套现成科幻 UI 皮肤：它会把界面再次推向通用面板。参考了 [Kenney UI Pack](https://kenney.nl/assets/ui-pack) 的 CC0 资源，但它的整体形状语言不适合本次精密仪器方向，因此没有导入。

实际引入的是 [思源黑体 CN](https://github.com/adobe-fonts/source-han-sans/tree/release/SubsetOTF/CN) 与 [IBM Plex Mono](https://github.com/google/fonts/tree/main/ofl/ibmplexmono)。两者官方许可为 SIL OFL 1.1；本次保持原始字体文件，随附许可和来源 / SHA-256 清单。它们提供稳定的中文和仪表排版，不依赖生成式插画来填补布局问题。

完整美学、各页面布局、组件状态和 Unity 实施顺序见 `ui-design-system.md`；可交互样板见 `ui-art-direction-preview.html`。样板是设计验证工具，Unity 的真实训练与通关仍由既有计算核心执行。
