# Learning Foundry / 学习工坊：成品制作设计

版本 0.2 · 2026-10-02 · 目标玩家：有高中数学基础，没有深度学习经验。

本文件把已有的 55 节点教学关卡设计推进为 Unity 游戏的制作规格。商业发行目标是 Windows / Steam 单机买断制解谜建造游戏，最终由玩家搭出并训练自己的手写数字分类器。名称为工作名，定名前需要单独检查商标与商店重名。

当前交付为Unity0.5.0：55关首轮玩法与数值验收已接通。原有17关标量接线，后续38关顺序张量积木与实验台；实际MNIST训练、卷积/池化、手写输入和模型导出已实现。详细实现范围见 campaign-playable-v05.md。不能把本文件的目标规格作为当前游戏已经具备的功能宣传。

## 1. 玩家为何愿意造这台机器

玩家接手一间停摆的工业维修工坊。旧设备能进行计算，却不能适应新货物；玩家需要从传感器、放大器和零点校准开始，把只会执行固定规则的装置修成能根据样本校准自身的机器。最终接到档案馆的委托：识别不同工人手写的数字，把混乱的档案送到正确柜格。

叙事通过短委托、设备缺陷、修复前后对照和工坊逐步恢复供电来表达。每份委托开头控制在几句内，数学解释放在可回看的维修手册中。故事奖励是设备真正能处理新的情况，并成为下一个项目的工具。

核心成就感来自三个层次：看见一条线路正确传递数值；把亲手拼出的线路封装为可以复用的零件；让这些零件组成的机器开始自行学习。章节终点必须出现可操作的大设备，避免玩家只积累一排通关徽章。

| 阶段 | 宏观项目 | 可带走的成果 |
|---|---|---|
| P + A | 手动校准分拣仪 | 可调计算器、双路混合器、误差计、平均器 |
| B | 自动校准引擎 | 自己搭好的反向规则、更新器、训练流程 |
| C | 解决 XOR 的非线性分拣器 | 多层网络和已训练参数 |
| D | 批量信号处理装配线 | 具有形状接口的向量/矩阵/Dense 盒子 |
| E | 十分类数据检验站 | 正确区分训练、验证与最终测试的流程 |
| F | 会看局部图案的视觉工坊 | Conv、Pool、Flatten 及可展开的内部结构 |
| G | 手写档案分类机 | 自己拼接、训练、冻结并接受最终验收的分类器 |

## 2. 单关节奏与教学契约

一关以一个主要新知识点为中心。循环为：接到设备规格 → 用已有工具观察缺陷 → 收到新零件的短说明或专门实验 → 构建/修复 → 用探针观察实际值 → 在多组样本上验收 → 把成果带去更大的机器。

已有 `levels.json` 中每关的 `teaching.text/demo/check` 与 `visualization.main/interaction/failure/completion` 是制作合同。每个玩家可见的新模块必须满足以下之一：第一次出现有清楚的短说明和可操作示例；或者有一关围绕它的输入、输出与行为进行实验。新功能的名字出现在奖励栏，并不等于玩家已经理解它。

首见模块的说明顺序固定为：它解决什么设备问题；端口接受什么；一次真实输入输出示例；玩家现在要验证什么。讲义可以收起，随时从模块右键或维修手册重开。首次解锁播放短装配动画，以后跳过。

正式版加入可观察的“先预测、再执行”：玩家先选参数会向哪边变化、哪个端口将变大，执行后查看真实差异。这些预测帮助玩家思考，不以答题界面替代线路建造，不在构建主线中重复考定义。

验收允许不同的等价线路。数值用例覆盖负数、零、重复使用、新输入和必要的参数变化；任务有结构要求时，要求必须写在委托中。例如 A04 的三个实际参数、A06 的两个独立实例。失败应指出具体样本或端口，而不只给“答案错误”。

教学阅读不是唯一入口：无经验玩家可操作短演示，有经验玩家可直接构建；逐步提示只帮助定位一处问题。完整答案不作为常驻解锁按钮。过关没有读秒压力，性能优化与零件数量放到可选支线。

## 3. 工作台与建造系统

主视图采用 2D 实体控制台，固定摄像机，避免玩家同时学习 3D 摄像机和深度学习。中心为可平移缩放的装配板，左侧为委托手册，右侧为联动仪表，底部为零件抽屉与运行控制。复杂图可以进入全屏装配模式，所有模式保存同一设备。

实体模块具备种类标识、端口名、可选数值读数、选中边框、错误灯和螺丝。电缆可以改变走线，但走线形状不影响计算。高亮、标记和声音同时表达状态，颜色不是唯一信息来源。大图隐藏次要读数，选中或探针悬停时显示细节。

正式建造交互须包含：多选/框选、批量移动、吸附、线路替换预览、撤销/重做、节点重命名、复制/粘贴、对齐、局部搜索、缩放到选择、快捷键重绑定。拖动不应误触运行；接线时先验证端口类型和形状，错误线路留在光标上并说明原因。删除模块会列出受影响连接，并支持撤销。

封装分为“蓝图定义”和“实例参数”。蓝图有稳定 ID、版本、输入/输出接口、内部图和兼容信息。新实例默认拥有独立参数；显式共享参数必须经过后续专门教学，并有明显共享标记。玩家可打开盒盖观察同一套实际数据和梯度，展开视图不创建第二份计算结果。

当前 A06 已实现整张 A04 单输出机器的封装与独立实例；正式版扩展到任意子图、多输入/输出、接口排序、盒子重命名、更新定义时的兼容检查和嵌套蓝图。不能直接把一个未连接的子图打包为“通过验收”的零件。

沙盒应使用已经学会的零件，另设“完整零件实验室”供熟悉深度学习的玩家使用。主线保存每关工作台以及玩家的蓝图库。沙盒设备与主线验收互不覆盖，玩家可手动导入蓝图。

## 5. 后续 38 个节点如何落地

继续使用现有关卡树的所有前置 AND 关系，选修支线不阻塞必修。C 章先完成到 C05 的 XOR 装置，作为完整 Demo 的候选终点；E/F 两条线路在 D06 后分支，并在 G01 汇合。具体每关的知识点、玩法和结果可视化仍以 [关卡设计](level-design.md)、[可视化规范](visualization-design.md) 为准。

| 批次 | 核心工程增量 | 章节验收设备 |
|---|---|---|
| C | 正分支/激活、多个可调层、分类判定、二维区域采样 | 同一训练器从线性失败走向 XOR 成功，显示真实决策边界 |
| D | 张量存储、形状推导、广播/归约、矩阵算子、批次、Dense | 标量线路展开后与矩阵盒子数值和梯度一致；批次没有漏掉样本 |
| E | 数据集和随机种子、标签编码、数值稳定的分类损失、验证隔离 | 训练集与验证集分别统计，训练改善不自动等于泛化改善 |
| F | 图像局部窗口、卷积参数共享、边界/步幅、池化与回流索引、Flatten | 滑动窗口和特征图来自实际卷积；池化可追踪梯度回到哪个位置 |
| G | 模型装配、训练预算、冻结模型、密封最终测试、自由手写板 | 输出十类分数、预测、真实类别、混淆矩阵和不同分割的指标 |
| S01–S08 | 等价优化、动量状态、泛化与可解释实验等选修 | 每条支线有专门引入、真实比较与独立成果，不提前开放主线未教的功能 |

Conv、Pool、Dense 等高阶模块的零件外形保持统一，而输入/输出端口上增加形状铭牌。形状不符时，连接预览就解释“此处需要 28×28×1，你给了 784”。点击展开看到已有基本运算或窗口示意；教学逐元素模式与快速训练模式共享算子语义。

必须先给每个新算子写 Forward/Backward 与形状契约，再设计教学关和可视化。ReLU 在 0 的梯度约定为 0；池化平局用稳定的首个索引；共享卷积核的所有窗口梯度累加；广播梯度沿广播维归约。这些约定既进入手册，也进入验收数据。

## 6. 数值执行与本机训练

当前引擎对玩家线路建立可观察的运算带。加法/乘法的反向过程实际求值玩家保存的规则图；梯度按使用路径累加；参数更新实际求值玩家更新器；四个样本的损失和梯度归约实际使用玩家平均器。该链条已经通过与有限差分对照和真实训练验证。

正式版继续保留两种执行方式：教学模式单步、记录中间值、展开盒子；训练模式编译相同图、批量计算，只抽样显示可视化。切换只改变速度与记录密度，不改变答案。仪表展示真实训练结果，动画根据记录播放，不伪造下降曲线。

CPU 是必需后端，保障普通笔记本能完成主线。MNIST 阶段先限定小模型、分阶段样本规模和训练预算，再根据测量优化张量内存、计算调度和向量化。把每个像素都展开成 uGUI 节点不会用于整套数据训练。

GPU 训练是后续性能项目。建议先完成 CPU 张量参考实现，再评估 Unity Compute Shader 后端：GPU 前向、反向、归约与参数更新都要实现并和 CPU 对照，不能只调用推理接口就称为训练。Unity 提供计算着色器能力，但本项目尚未编写或验证这些训练内核。[Unity 2022.3 Compute Shader 文档](https://docs.unity3d.com/2022.3/Documentation/Manual/class-ComputeShader.html)

数值后端通过 `ExecutionBackend` 接口切换，运行前显示选择、支持情况与预计预算。显存不足、计算不支持或内核失败时提供 CPU 恢复；暂停/取消在批次边界生效。正式训练应从 UI 主线程分离，并给 CPU/GPU 预算上限，避免让工作台失去响应。

当前 17 关是极小的四样本标量训练，每帧有限步运行；没有宣称适用于完整图像数据。独立原生数学框架可作为未来对照或性能备选，但发行包不能要求普通玩家配置开发环境。

## 7. 手写数字终章与游戏性

终章不提供已经训练完的模型。玩家从自己的模块库拼出结构，检查接口与参数预算，运行可中止的真实训练，查看训练/验证指标，冻结模型，再提交密封测试。MNIST 的实际数据来源、校验值、许可和分割策略在实现前固定；当前发行包尚未含 MNIST。

训练、验证、最终测试各自有不同颜色和封印标记。训练数据用于更新；验证数据用于方案比较；最终测试在模型冻结后解封，防止把测试反馈当训练目标。玩家自由手写是独立演示，不能把“识别了我写的一个数字”当总体准确率。

预设主线目标可暂定“分类准确率达到基础线”；更高准确率、参数少、训练快、抗扰动作为挑战。已有 90%、95%、50k 参数等数字属于策划候选，需要用实际后端与模型试跑后再定，不写成当前成绩或系统性能承诺。

失败结果应让玩家继续创造：显示哪些数字容易混淆、哪些样本过于自信、卷积窗口关注哪里。可以保存不同结构在相同条件下比较，也能打开旧机器。成品的终章允许玩家用 MLP 或 CNN 等不同正确方案通过基础任务。

## 8. 视觉、声音与反馈

详见 [美术规范](art-direction.md)。整体使用青黑钢板、黄铜、米色铭牌与少量青色灯，避免每一种算子都变成独立美术体系。背景负责场景气氛，装配板负责可读性，重要信号用明度与形状强调。

每关结果遵循同一逻辑：输入样本可定位；中间值可沿线路追踪；目标与实际值可并排比较；失败位置可再次运行；通关设备可打开回看。章节采用不同仪表：标量读数、残差/损失刻度、回流贡献、二维边界、形状叠层、特征图、混淆矩阵。

声音表达操作和机器状态：插线接通、参数刻度、无效连接、训练启停、验收通过。背景机械声可以独立关闭，不用频繁警报惩罚数学试错。量产前替换/补齐当前简单继电器点击音，统一音量与声音来源记录。

## 9. 存档、内容工具与发行工程

正式存档保存稳定的设备 ID、蓝图版本、实例参数、关卡状态、提示进度、设置和训练模型快照；不依赖场景对象实例 ID。升级必须有版本迁移，损坏恢复保留原文件。云存档恢复按时间和版本提示冲突，不静默覆盖玩家的大图。

关卡与模块定义应转为有编辑工具支持的内容资源：创建关卡、指定前置与零件白名单、导入教学文本、编辑样本、选择仪表、预览验收、检查未教模块、验证形状和预算。现有 JSON 仍作为课程与依赖的权威来源，Unity 数据副本要有同步检查，防止两份关卡内容漂移。

测试分为数学契约、任务判定、存档迁移、UI 交互、性能与发行包。判断测试必须既有可接受方案，也有应拒绝的近似错误；不能只测试某张参考线路。GPU 和 CPU 允许规定的数值容差，通关判定优先稳健指标，不要求所有硬件位级一致。

目标 QA 矩阵：1080p/1440p、16:9/16:10/超宽屏、中文/英文、大字号、无独显 CPU 模式、集显/独显、长时间训练与暂停、异常退出恢复、大型蓝图、Steam 离线启动。Steam Deck 与手柄支持独立评估，完成前不标“已支持”。当前只验证本机 Windows 构建和自动运行。

| M2 完整主线 Alpha | 47 必修与 8 选修实际可玩、CPU 张量后端、Conv/Pool、手写数字终章 | 每个新模块都有首次教学；所有章节设备连贯；CPU 可完成核心任务 |

Demo 是否收费、正式定价与预计时长在 M1/M2 试玩数据之后确定。无需先把全部高级主题塞入第一版；正式基础商品应当有从逻辑零件到完整分类器的可达终点。

## 11. Steam 工作清单

Steam 的商店页和游戏构建需要分别准备并提交审核；Coming Soon 页面展示时间也属于发布条件，不能只按本地 exe 完成日期安排发售。按照当前官方文档安排审核缓冲与页面至少两周的公开展示；实际时间以账号后台和临近发布的官方要求为准。[Steam 发布流程](https://partner.steamgames.com/doc/store/releasing)

成品需要真实游戏截图、预告、商店/库图形、准确系统要求、语言支持、启动项、安装包与内容调查。成果评价、Steam Cloud 和 Workshop 可在本地玩法稳定后分批增加；离线运行不能依赖 Steam 网络认证来进行基础数学计算。Steam 集成功能以实现和测试为准，当前原型未集成 SDK。

当前工坊背景由 AI 图像工具生成，实际随游戏分发时，应按 Steam 内容调查对玩家消费的预生成美术如实说明。普通分类训练与分类标签输出不应仅因“机器学习”名称就混同为运行时生成叙事/图像服务；若以后增加这种服务，重新检查对应调查要求。[Steam 内容调查](https://partner.steamgames.com/doc/gettingstarted/contentsurvey?l=english)

本轮没有创建 Steam 应用、付款、提交审核或发布商店。下一步最有价值的工作是让新玩家从零试玩当前闭环，修复接线与教学卡点，然后完成 C 章非线性设备。
