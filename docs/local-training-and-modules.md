# 本地训练与模型模块设计

更新日期：2026 年 10 月 2 日。

本文补充回答两个设计问题：游戏能否用玩家 CPU 或 GPU 真实训练模型，以及后期能否通过封装与拼接卷积、池化等模块完成模型搭建。推荐方案是本机执行真实训练、逐级形成可展开的模型部件，并以 MNIST 手写数字分类作为完整版本的终章候选。以下实现路线与关卡都是设计建议，尚未形成可运行原型或设备性能基准。

## 在玩家设备上执行真实训练

可以在玩家设备上执行模型正向计算、损失计算、反向传播和参数更新，训练后保存实际学到的权重。TensorFlow.js 官方教程已经展示了在浏览器内训练手写数字卷积网络，并使用未参加训练的数据评估分类表现。[官方训练教程](https://www.tensorflow.org/js/tutorials/training/handwritten_digit_cnn)，[完整 Codelab](https://codelabs.developers.google.com/codelabs/tfjs-training-classfication/index.html)

建议的运行方式如下：

| 运行路线 | 用途 | 本项目建议 |
| --- | --- | --- |
| CPU 上的小型标量引擎 | 早期运算、单步梯度和小网络 | 自有引擎记录每个值和局部规则，便于玩家观察 |
| TensorFlow.js CPU 后端 | 张量运算与 GPU 不可用时的训练 | 保留可完成任务的 CPU 路线；在工作线程中运行或按小批次调度，保持界面可操作 |
| TensorFlow.js WebGL 后端 | 支持设备上的本地 GPU 训练 | 作为浏览器版首先验证的 GPU 路线，逐项检查模型算子和反向计算 |
| TensorFlow.js WebGPU 后端 | 后续 GPU 执行选项 | 原型验证目标模型的完整训练链后再接入 |
| 原生桌面训练运行时 | 未来桌面版的 CPU 与支持的 GPU | 如有需要可考虑 PyTorch 等本地运行时，配套处理平台、驱动和发行包 |

TensorFlow.js 文档说明了 CPU 后端与使用 GPU 着色器执行运算的 WebGL 后端，并推荐 WebGL 或原生 TensorFlow 后端用于训练。WebGPU 后端的官方说明仍提示部分梯度运算支持不足，因此本项目需要验证具体模型，不能仅凭浏览器支持 WebGPU 就认定训练链可用。[平台与后端说明](https://www.tensorflow.org/js/guide/platform_environment)，[WebGPU 后端官方说明](https://github.com/tensorflow/tfjs/tree/master/tfjs-backend-webgpu)

原生 PyTorch 的官方入门示例也支持把模型与数据放到可用加速设备上执行训练，设备不可用时使用 CPU。这是桌面路线的实现参考，具体发行环境仍需另行验证。[PyTorch 官方入门](https://docs.pytorch.org/tutorials/beginner/basics/quickstart_tutorial.html)

首版建议优先完成 CPU 上的基础体验，再为视觉章节接入经过验证的 GPU 路线。小数据、小模型便于快速实验；实际吞吐量与训练耗时取决于设备、执行后端、网络和数据规模，需要做真实测量。

训练期间允许暂停、继续与保存。可以提供运行负载设置，控制批次调度频率与占用；性能较弱的设备使用较小批次或较少的训练样本进行实验。基础任务保持相同学习目标，额外挑战再扩大数据和模型规模。

## 用同一套构建支持观察和快速训练

玩家的接线图需要成为真正可执行的模型描述。建议由同一份图记录节点、端口、参数、共享关系与模块结构，再提供两个执行方式。

**观察方式**选择一个样本或一个小批次，记录真实中间值与梯度，支持单步运行和展开。**快速训练方式**将支持的操作映射到张量后端，批量更新同一组参数。玩家完成训练后，可以带着学到的权重返回观察方式，检查一个被错分的数字。

标准模块进入快速执行，需要有明确的等价映射，并验证正向结果、梯度和参数更新在约定精度内一致。自定义子图按照其实际运算执行；如果玩家编辑了反向规则，执行必须保留该规则的含义。把自定义模块换成某个高效内核需要额外证明对应关系，不能只依据名称或少量测试结果。

这样，模块封装可以减少界面复杂度，训练加速可以减少等待，而玩家之前搭建的数学规则仍然参与模型行为。

## 从基础运算逐步封装为模型积木

你提出的卷积 Conv 和池化 Pooling 很适合成为后期模块。封装最好发生在玩家已经做过一个小规模版本、检查过结果之后。

| 层级 | 玩家理解的内部过程 | 可以保存与复用的模块 |
| --- | --- | --- |
| 标量运算 | 加法、乘法、参数、局部反向规则 | 基础算子 |
| 计算单元 | 加权求和、偏置、非线性 | 神经元与 Dense 层 |
| 空间运算 | 小窗口计算、窗口移动、权重共享 | Conv2D 层 |
| 汇聚运算 | 小区域取平均或最大值，以及梯度怎样传回 | AveragePool 或 MaxPool 层 |
| 多层组合 | 卷积、激活与池化协作 | 特征提取块 |
| 完整系统 | 特征提取、分类输出与训练流程 | 可训练的手写数字分类器 |

例如，卷积关卡先给一幅小图和一个 3×3 窗口，让玩家完成一次加权求和；再让同一个窗口滑过不同位置，形成特征图；最后让窗口中的权重通过训练更新。完成这些任务后，玩家可以保存参数化的 Conv2D 部件，选择卷积核大小、输出通道、步幅和边界处理。

池化关卡可以先显示四个数，让玩家观察平均值和最大值的行为。进入反向阶段后，平均池化展示贡献如何分配，最大池化展示梯度传回取得最大值的位置。并列最大值采用固定且与执行后端一致的规则，前期样本可以先避开并列情况。

后续允许玩家把 Conv、ReLU 和 Pooling 封装成一个特征提取块，复制、重命名并继续组合。模块始终可以展开查看原来的结构；玩家可以逐步从细部计算转向网络结构设计。

TensorFlow.js 的 Layers API 支持串行层组合和无环的功能图组合，也提供形状推断。它可以作为这类积木编辑器的执行基础，游戏负责定义操作方式、学习过程和模块内容。[模型与层的官方说明](https://www.tensorflow.org/js/guide/models_and_layers)

## 每个模块需要的接口

| 接口内容 | 作用 |
| --- | --- |
| 输入与输出形状 | 连接时检查维度，自动展示图像尺寸、通道和特征数量的变化 |
| 可配置项 | 指定通道数、卷积核、步幅、池化窗口等结构参数 |
| 可训练参数 | 管理实际权重、偏置与初始化 |
| 正向与反向定义 | 支持真实训练及教学中的单步检查 |
| 展开结构与说明 | 玩家可以查看部件内部运算和学习来源 |
| 参数数量与计算量估计 | 支持结构优化与资源预算任务 |
| 版本与执行映射 | 支持存档，以及观察方式和快速方式之间的对应 |

复制一个模块时，默认复制结构并创建独立参数；如果玩家明确选择权重共享，才引用同一组权重。复制结构、复制已训练权重和共享权重应作为不同操作表达，避免多个看似独立的层意外联动。

学习中的不兼容连接应有具体反馈。例如，按照本游戏规定的 Dense 接口，输入需要是一个批次的特征向量；连接特征图时，可以显示其空间尺寸和通道数，并提示使用 Flatten 或其他适合的汇聚模块。

## 用 MNIST 作为终章候选

MNIST 包含 0 到 9 的手写数字，图像形状为 28×28×1，标准划分为 60,000 个训练样本与 10,000 个测试样本。它能够把像素、特征提取、多分类、训练和评估放进一个规模适中的任务中。[TensorFlow Datasets 的 MNIST 说明](https://www.tensorflow.org/datasets/catalog/mnist)

终章建议设计为修复邮政分拣站的手写数字读取系统。玩家使用自己的模型部件识别数字，检查容易混淆的笔迹，并在完成训练后亲自在画板上写数字。这个用途可以延续原方案中的分拣站设定。

进入终章前，建议安排以下过渡：

1. 用少量样本区分两个数字，理解像素输入和类别输出。
2. 用全连接网络完成十类分类，形成可以比较的基础模型。
3. 学会并封装卷积、激活和池化，查看它们生成的特征图。
4. 在相同数据与训练预算下比较模型，尝试减少参数或改进表现。
5. 进入完整任务，处理验证表现、错分样本与个人手写输入。

任务可以接受满足约束的多种网络结构。全连接网络能够参与图像分类，卷积应通过参数共享、局部特征和资源约束体现用途。TensorFlow.js 的官方手写数字教程也说明了 Dense 层可以用于图像分类。[官方 Codelab](https://codelabs.developers.google.com/codelabs/tfjs-training-classfication/index.html)

## 一个可供验证的终章参考网络

下面的结构用于估算范围和规划模块，并非已经训练过的模型或标准答案。采用通道在最后的图像布局，卷积步幅为 1、使用 same 边界处理，池化窗口和步幅均为 2；表中省略批次维度。

| 模块 | 输出形状 | 可训练参数 |
| --- | --- | ---: |
| 图像输入 | 28×28×1 | 0 |
| Conv2D 3×3 8 通道 | 28×28×8 | 80 |
| ReLU | 28×28×8 | 0 |
| MaxPool 2×2 | 14×14×8 | 0 |
| Conv2D 3×3 16 通道 | 14×14×16 | 1,168 |
| ReLU | 14×14×16 | 0 |
| MaxPool 2×2 | 7×7×16 | 0 |
| Flatten | 784 | 0 |
| Dense 32 | 32 | 25,120 |
| ReLU | 32 | 0 |
| Dense 10 | 10 | 330 |
| Softmax 结果显示 | 10 个类别概率 | 0 |

总计 26,698 个可训练参数，计算包含各有权重的层的偏置。这是较小的网络，但总训练成本仍由激活、反向计算、批次和训练步数决定，不能仅凭参数数量推断耗时。

训练使用交叉熵。实现时需要明确损失模块接收 logits 还是概率；若使用接收 logits 的数值稳定交叉熵，损失分支直接连接 Dense 10 的输出，Softmax 用于显示类别概率。图中的连接和编译后端必须遵守同一种约定。

## 终章评估与实际手写体验

从标准训练数据中另划出固定验证集，训练过程用验证表现帮助玩家调整结构和配置；标准测试集用于最终评估。早期实验使用按类别覆盖的较小训练子集，后期按任务扩大数据，保证实验速度与数据角色清楚。

通关阈值和训练预算应根据 CPU 路线、GPU 路线和参考模型实测后确定。评分重点可以包括分类表现、参数数量、推理计算量，以及预先定义的轻微平移或噪声任务。实际耗时用于帮助玩家判断等待时间，避免把显卡性能直接变成学习成绩。

个人手写画板属于体验与进一步诊断。画板图像经过灰度化、裁剪、缩放和居中等与模型约定一致的处理，再进入训练好的网络。个人笔迹和画板输入可能与数据集分布不同，标准测试上的表现与画板体验需要分别观察。

最终可呈现的成果包括玩家保存的网络结构、实际学到的权重、验证与测试结果，以及对错分数字的检查记录。玩家可以继续尝试更小的网络、不同模块组合或增加训练样本，形成完成主线后的开放挑战。

## 下一步原型验证

建议优先验证三个具体能力：

- 同一个小模型可以在 CPU 上训练，并在至少一个 GPU 后端上执行完整训练；核对输出、梯度和更新行为。
- 玩家封装的 Dense 或 Conv 模块可以被保存、实例化、展开，并正确处理独立参数与共享参数。
- 用小规模 MNIST 子集完成一次真实训练，记录数据准备、训练、验证和交互延迟，再据此确定后续关卡预算。

现阶段已经查证本地训练与层组合的技术可行性。设备兼容性、实际速度、参考网络精度与游戏关卡难度仍需在本项目原型中验证。
